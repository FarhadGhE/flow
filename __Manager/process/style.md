# Style — how deliverables and replies look

- **Evidence.** Put a source link on every claim that accepts or rejects something; the user checks
  them.
- **Choices.** Any A-or-B decision gets a comparison table with a **bolded recommendation**. Field each
  side's best current option, and never treat an earlier choice as immovable. License-check what you
  recommend, model weights included.
- **Open items.** Every open item becomes a numbered question with a recommendation.
- **Costs.** Give every monthly cost a number, marked "as-of list price, re-verify at purchase".
- **Length matches importance.** Be direct and skip filler; expand only when asked. Give the shortest
  complete answer, not the shortest possible one.
- **Summaries for humans** (coordination summaries, results) are short and plain: how the work is set
  up and what the final state is.
- **Deliverables** are markdown files in the turn or round folder. Also send them to the user when the
  host can.
- **Messages the user drafts for others.** Keep the user's words. Fix only what is wrong and add only
  what was asked. Offer at most 2–3 variants with one bolded recommendation, as plain text in a fenced
  block, with no AI polish.
- **Replies that end a round** end with the receipt line, then the resume line (`turn.md`,
  `coordinate.md`).
